OT Risk Analysis – Guide

From the component list to the action plan. All by clicking, no command line.

The essentials in brief

1. OpenOpen the app in your browser
2. Create“Start a new analysis”
3. ComponentsAdd a device, scan or load a file
4. Search“Search for vulnerabilities now”
5. ResultView the action plan and save it as a PDF

To try it out without your own data: click View the example on the start page.

1Open the app

Open this address in your browser. It works on Windows, Mac, iPhone and iPad:

https://ot-risk-tools.github.io/ot-risikoanalyse/en/

The German edition is at https://ot-risk-tools.github.io/ot-risikoanalyse/. The DE button at the top of the app switches to it. Both editions share the same analyses on a device.

On a Windows PC with the start file

  1. Open the folder Programm Risk.
  2. Double-click OT-Risikoanalyse starten.
  3. A small black window opens, followed automatically by the browser with the app (German edition). Click EN at the top to switch to English.
Leave the black window open while you work. To quit, simply close that window. Your data has already been saved by then.

Only this way offers “Scan software” with one click and the extra backup as a file on the PC.

2Create an analysis

  1. Click Start a new analysis.
  2. Enter a name, e.g. “Wire drawing machine, customer Sample”.
  3. Choose how the machine is connected (without network / in the production network with remote maintenance / with internet or cloud connection).
  4. Click Create.

That is all you need at the start. Under 1 · Context you can refine things later: how dangerous would manipulation be for people? How bad is a standstill? Can updates be installed quickly? These settings determine how high the app rates a risk.

3Add components

Under 2 · Components there are three ways. You can combine them freely.

Way A: add a device (PLC, HMI, drive, switch, operating system …)

  1. Click Add a device.
  2. Type a keyword into the search field, e.g. “S7-1500” or “SCALANCE XC208”, and click Search. Searching the product list takes a few seconds.
  3. Click the matching product in the list.
  4. Enter the version (firmware level) or pick it from the suggestions.
  5. Save. The list now shows “✓ automatic check”.
The version matters: only with a version does the app find exactly the vulnerabilities that really affect that level.

Way B: scan software (PC software, Linux devices, containers)

Available on a Windows PC when the app was opened through the start file.

  1. Click Scan software.
  2. Choose the folder that contains the software: click a folder to go into it; “↑ up” goes back.
  3. State what is in the folder: a software project or installed software / a device file system.
  4. Scan this folder. The program Trivy searches the folder; this takes from a few seconds to a few minutes.
  5. Check the summary and click Add.

Trivy detects software packages. It does not detect the firmware of controllers, drives and network devices – that is what way A is for.

Way C: import a file

If you have a bill of materials (SBOM) in CycloneDX format from a supplier or from development: click Import a file, choose the file, Add.

4Search for vulnerabilities

  1. Click Search for vulnerabilities now at the bottom.
  2. Wait until the progress bar has finished. With many devices this takes a while because the vulnerability database allows only a few queries per minute. The app waits by itself.
  3. At the end the app shows what was found.

If it says that components could not be checked automatically: click Assign and choose product and version as in way A. Then search again.

5Assess vulnerabilities

Under 3 · Vulnerabilities you find all findings, the most dangerous first. On the right you see the risk before → after.

  1. Click Apply all recommendations. This selects the app's proposal for every vulnerability.
  2. Optional: tap a single vulnerability. It shows why the risk is that high, and you can select or deselect measures.
  3. If a vulnerability does not apply to the machine, set the status to Not affected and give a short reason.

What the coloured labels mean

  • actively exploited: this vulnerability is already being used in real attacks. Highest urgency.
  • acceptance only after patch/replacement: with immediate measures alone the risk stays above your limit. It only drops with the update. Someone has to carry this interim risk deliberately.
  • decision needed: no available measure is enough. Those responsible have to accept the risk formally or replace the component.

6Action plan and report

Under 5 · Measures & report the app sums everything up:

  • Immediate / Short term / Planned: what to do in which order, with concrete steps and the reference to the IEC 62443 standard.
  • Decisions needed: points that someone has to decide explicitly.
  1. Click Print the report / save as PDF.
  2. In the print window choose “Save as PDF” as the printer and save.

Further outputs: a table for Excel (CSV) and a CycloneDX file with VEX for customers or other tools.

Data and backup

  • Everything is saved automatically. There is no save button.
  • The data stays in the browser of the device you are using. Each device has its own data.
  • Via ⋯ at the top right: Save a backup, Load a backup, pass on a single analysis, delete all data. Use the backup file to move analyses between devices.
  • If you clear your browser data, the analyses are gone. Save a backup regularly.
  • The data is not encrypted. For confidential customer data use a device with disk encryption.
  • Only queries for product names and CVE numbers go to the internet (to NVD, FIRST and CISA). Your project data does not leave the device.

iPhone, iPad and Mac

  1. Open the address on iPhone or iPad in Safari.
  2. Tap Share (the square with the arrow pointing up).
  3. Choose Add to Home Screen. The app then sits on the device like any other app.

On a Mac in Safari: File → Add to Dock. Everything works there except “Scan software”.

If something does not work

The top of the page says “The start window is closed” or the browser shows “This site can't be reached”.
The black start window is no longer running. Double-click “OT-Risikoanalyse starten” again. Your entries are not lost.
The product search finds nothing.
Use a shorter keyword (only the type designation, e.g. “XC208”). Not every product is in the list – in that case create the component anyway and add vulnerabilities by hand using the CVE numbers from the vendor advisory (step 3, “Add a single vulnerability by hand”).
The search takes a long time or reports “NVD overloaded”.
The public database is busy at times. Wait a few minutes and search again. What has already been found is kept.
“Scan software” says Trivy is not installed.
The app then shows the one command that installs Trivy once.
The scan finds no packages.
Repeat the scan with the other setting (“Installed software or device file system” instead of “Software project”) or choose a folder one level up.
I clicked the wrong thing.
Every choice can be changed. Nothing is deleted without a confirmation prompt.

Terms in brief

CVE
Unique number of a publicly known vulnerability, e.g. CVE-2021-44228.
NVD
Public vulnerability database of the US agency NIST. The product list and the vulnerabilities come from there.
CVSS
General severity of a vulnerability from 0 to 10, independent of your machine.
EPSS
Estimated probability that the vulnerability will be exploited within the next 30 days.
Actively exploited (CISA KEV)
List of vulnerabilities that are known to be used in attacks.
Risk (1 to 25)
Likelihood × impact, rated for your machine and its environment. Up to 4 low, up to 9 medium, up to 14 high, from 15 critical.
Acceptance threshold
The risk value up to which a risk is considered tolerable. Default: 4.
SBOM / CycloneDX
Bill of materials of a machine's software; CycloneDX is a standard format for it.
VEX
Addition to the bill of materials: which vulnerability really affects the product, and what is its status?
Trivy
Free scanner that detects software packages in a folder and reports their vulnerabilities.
IEC 62443, SR, SL-T
Series of standards for the security of industrial plants. SRs are individual requirements from it; SL-T is the target protection level (1 to 4).
